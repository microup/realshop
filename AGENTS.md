## Обзор проекта

Каноническое расположение проекта: `D:\dev\src\realshop\` (remote `https://github.com/microup/realshop.git`). Любые копии этого дерева в других папках — снимки для чтения; код менять только здесь.

RealShop — MelonLoader-мод для *Car Mechanic Simulator 2021* (Red Dot Games). C# / .NET Framework **4.8**, `OutputType=Library`, сборка в `RealShop.dll`. Игра собрана на **IL2CPP**, поэтому мод работает через MelonLoader 0.6.1 + UnhollowerBaseLib 0.4.18 и Harmony **2.9.0** (`using Harmony;` + `HarmonyInstance` — это алиасы Harmony 2.x, не устаревшая 1.x). Мод убирает из магазина запчасти машин старше `RemoveCarsOlderThanYear` (2005), вводит restoration ceilings (потолок восстановления, v0.3.9), экономику (sell-cap, labor cost, donor condition), маркеры потребности/апгрейда на свалке (v0.3.10) и условную экономику v0.3.11: цена продажи машины и деталей зависит от состояния, труд — гипербола `1 + k·cond/(1−cond)`, превью цены/прироста следующего цикла на кнопке Start; индикатор маржинальности (`MarginService`, в разработке как 0.3.11-devN): зелёный `$`-маркер на карточках и зелёная/красная раскраска превью, когда цикл ремонта окупается/не окупается (resale-канал детали + канал машины). С 0.3.11-dev5 — кап качества аукциона: звёздный рейтинг каждой аукционной машины зажат к `AuctionMaxRating` (по умолчанию 1); с 0.3.11-dev6 — на аукционе только машины старше `RemoveCarsOlderThanYear` (пул `GetCarsForScene(SceneType.Auction)` + фильтр списка `AuctionManager.GenerateCars`); с 0.3.11-dev7 — в автосалоне только современные машины: сетка `ShopCarWindow` скрывает машины с годом ниже `RemoveCarsOlderThanYear` (год — из id машины через `CarData`, фолбэк — год в имени; знаковое сравнение, скрытие только подтверждённо-старых); с 0.3.11-dev8 — задания «собрать машину с нуля» (`EnableBuildFromScratchJobs`, **по умолчанию выключено**): при принятии приезжает голый остов (подавление `CarLoader.Create*`), в задании указаны минимальные качества кузова/деталей/интерьера (разброс из `BuildJob*Min/MaxQuality`, выводятся хешем из `job.id`), генерация только на ретро-машины из Order-пула, срок `BuildJobDeadlineDays` (7), метка «КРАЙНЕ СЛОЖНОЕ» и отдельный слот в окне заказов, завершение блокируется при несоответствии требованиям, награда — цена готовой машины × `BuildJobRewardMultiplier` (5) **сверху** к игровой выплате; с 0.3.11-dev9 — рамка случайная (без повтора предыдущей), задание доступно с `BuildJobMinLevel` = 1 (окно генерации до `BuildJobMaxLevel` = 80), непринятое предложение меняется каждые `BuildJobOfferSeconds` (120 с), при принятии выдаётся предоплата `BuildJobAdvancePercent` (30 %) от награды и удерживается из итоговой выплаты; с 0.3.11-dev10 — в задании **четыре** требования (кузов, детали, **рама**, интерьер; рама = среднее `CarPart.StructureCondition` по установленным деталям, ключи `BuildJobFrameMin/MaxQuality`), срок считается в днях (`Job.timeToEnd` — часы, поэтому `BuildJobDeadlineDays * 24`), все ячейки окна заказов разблокированы (`BuildJobUnlockAllOrderSlots`), принятие заказа перехватывается в `OrdersWindow.AcceptOrderAction` (там игра считает приём: предоплата и зачистка машины теперь реально срабатывают), по умолчанию приезжал **собранный** автомобиль (`BuildJobStripMode = off`), а тексты мода выбираются по языку игры: русский — для русской локализации, английский — для остальных (`BuildJobTextLanguage = auto`/`ru`/`en`, `RealShop/Jobs/BuildJobText.cs`). С 0.3.11-dev12 — набор подавляемых методов задаётся списком `BuildJobStripMethods` (живой ключ cfg, правка без пересборки): `CreateWheels`/`CreateWheelsIO` из него **исключены по умолчанию** — подавление колёс вешает игру на загрузочном экране приезда (подтверждено live: последняя строка лога перед зависанием `strip: skipped CreateWheels`). С 0.3.11-dev13 — список защищён: пустое/пробельное значение возвращает дефолт, незнакомое имя и `CreateWheels`/`CreateWheelsIO` дают Warning, закрытие окна в `CreateBonusParts` не зависит от наличия метода в списке, а одноразовые логи загрузки сбрасываются на каждом арминге; в dev14 добавлено значение, пустое после разбора (только запятые), — тоже дефолт + Warning `no valid names`; в dev15 окно зачистки закрывается **в commit** (`strip disarmed: accepted`), а не в `CreateBonusParts` — игра создаёт кузов/салон/детали после `CreateBonusParts` и до подтверждения принятия, из-за чего на остове оставались кузовные детали; в dev16 `ReconcileActiveJob` больше не стирает принятое задание (принятый заказ всегда отсутствует в `generator.Jobs` — теперь проверяется и `generator.selectedJobs`), фолбэк «место+модель» не срабатывает при `placeNo < 0`, а в dev17 null-список в `ReconcileActiveJob` трактуется как «неизвестно» (снятие запрещено), попадание в `selectedJobs` логируется один раз, и строка коммита больше не Warning. С 0.3.11-dev18 — набор подавления по умолчанию сокращён до `CreateExterior,CreateCarLightParts,CreateBonusParts`: игра снова создаёт мотор, салон, детали и кардан (изношенными), и `OrderGenerator.PrepareJob` получает чем наполнять список «ДЕТАЛИ ДЛЯ РЕМОНТА» (при полном подавлении в нём оставалась только замена масла, вкладки мотора и салона были пустые). С 0.3.11-dev20 — набор подавления по умолчанию восстановлен до полной зачистки: `CreateEngine,CreateEngineAsync,CreateInterior,CreateParts,CreateDriveshaft,CreateExterior,CreateCarLightParts,CreateBonusParts` (по-прежнему без `CreateWheels`/`CreateWheelsIO`); live-лог с `methods=CreateExterior,CreateCarLightParts,CreateBonusParts` показал на машине задания мотор, системы, ходовую, салон и запчасти, что прямо противоречит ТЗ «только остов», а пустой список работы заказа — принятая плата (список строит игра из установленных деталей, завершение считает `Validate` мода); `BuildJobPanels.PanelsSuppressed()` с dev20 проверяет `CreateExterior` точным именем через `BuildJobStripTarget.IsMethodEnabled`, а не подстрокой в cfg-списке; в dev20 же гейт завершения перестал падать открыто — `catch` в prefix `GameScript.EndJob` больше не заканчивается `return true` (исключение в `Validate` на остове с пустыми списками открывало выплату ×5 за недостроенную машину): при `BuildJobBlockEarlyFinish` исключение блокирует завершение с Warning `EndJob gate failed`; и важно для поддержки: MelonPreferences не перезаписывает существующий ключ, поэтому старый cfg с сокращённым списком сохраняет собранную машину — правится `BuildJobStripMethods` в cfg, живой список виден в стартовой строке `methods=…`. Кузовные детали убираются игровым механизмом `CarLoader.SetRandomMissingPanels(BuildJobStripPanelChance)` (дефолт 100) из postfix `CarLoader.CreateChassis` и prefix `OrderGenerator.PrepareJob(CarLoader, Job)`: `CreateExterior` панели не создаёт (секция `[9_exterior]` конфига машины — только номерные знаки), панели приезжают вместе с шасси, поэтому их подавление в списке методов бессильно. Требование по кузову пропускается когда панели снимаются и ни одна не установлена (sentinel −1 как у рамы), а счётчики «снято»/«установлено» считают только не-панели, иначе снятые панели делают задание незавершаемым; имена панелей — `BuildJobPanelNamePrefixes` (`CarPart.name` по префиксам). Принятие заказа подтверждается тиком `BuildJobAcceptPatch.TickCommit()` из `RealParts.OnUpdate` (каждые 30 кадров пока есть кандидат): игра не обновляет окно заказов после принятия, поэтому commit только в postfix/`UpdateJobs` в live не наступал никогда — ни предоплаты, ни активного задания, ни гейта завершения, и окно зачистки оставалось открытым все 20000 кадров. С 0.3.11-dev19 — **предоплата перестала теряться**: `TryPayPendingAdvance` искала задание через `FindJobById` только в `generator.Jobs`, а принятый заказ всегда уходит из этого списка (это и есть сигнал принятия), поэтому маркер предоплаты снимался молча и 30 % не выплачивались никогда; теперь предоплата считается по машине (`FindCarLoaderByOrder` по `CarLoader.orderConnection == jobId`), список заказов в расчёте не участвует. **Карточка задания больше не уезжает в самый низ**: `DedicatedSlotIndex` ставит её сразу после карточек доступных заказов (раньше — в последний разблокированный слот, что при `BuildJobUnlockAllOrderSlots` = низ списка), перенос — `SetSiblingIndex` с защитой от повторного перемещения. **Соблюдено правило «нет файлов > 500 строк»**: `Config.cs` (1873) → `Config.cs` + `ConfigInit.cs` + `ConfigCarLists.cs` + `ConfigCarYearsA|B|C.cs` (массив `RetroPartYears` из 1216 записей стал тремя методами, склеенными `RetroPartYearsDefault()`, коды страниц CP1251 сохранены, содержимое сверено построчно); `Jobs/BuildJobService.cs` (1281) → `+Offers/+Advance/+Validation/+Prices` (partial); `Runtime/GarageNeedsRecon.cs` (879) → `+Prices/+Dump`; `Patches/RarityColorPatches.cs` (772) → `+Markers`; `Patches/RepairPatches.cs` (613) → `+RepairLaborPatches/+RepairCostPreviewPatches`; `Patches/EconomyPatches.cs` (527) → `+MoneyAndCarSalePatches`. ## Настройка окружения

- Требуется установленная игра **Car Mechanic Simulator 2021** с **MelonLoader** (проверено на game build 1.0.40).
- **Канонический путь игры: `D:\SteamLibrary\steamapps\common\Car Mechanic Simulator 2021\`**. Все `HintPath` в `.csproj` (21 ссылка) и `OutputPath` — абсолютные, от этого корня. Относительные `..\..\..\..\SteamLibrary\...` в `.csproj` запрещены (не совпадают с реальным расположением диска). Если игра в другом месте — правьте `HintPath` локально и **не коммитьте** это в `.csproj`.
- Конфиг мода создаётся игрой в `D:\SteamLibrary\steamapps\common\Car Mechanic Simulator 2021\Mods\RealShop.cfg` (MelonPreferences); секретов нет.


- NuGet не используется — только прямые `<Reference>` из каталога MelonLoader игры.

## Архитектура (кратко)

Поток: `RealParts` (MelonMod) → `OnApplicationStart` грузит `Config` и вызывает `PatchBootstrap.Install(harmony)` → `OnSceneWasLoaded(buildIndex==10)` инициализирует `RetroPartCatalog` (цены/скрытие магазина) → `OnUpdate` крутит `SceneUiController` и hotkeys. Игровые типы доступны через `CMS.*` (Assembly-CSharp) и `GameTypes.All()` (кэш рефлексии по сборке игры).
